# 跑团日志增强

> 在此先感谢原插件作者`檀轶步棋`和`JustAnotherID`提供的思路以及实现。另外，感谢骰主 `星·麒` 要求开源此插件。

为 SealDice 原生 `.log` 指令提供群聊侧的伴随增强：

- `.log on [名称]` 成功开启后，回复到该群上一次成功 `.log off`、`.log end` 或 `.log halt` 的位置。
- 原生 `.log new/on` 成功开启时开始计时；原生 `.log off/end/halt` 成功结束时停止计时并显示本次和累计时长。
- 原生 `.log new <新名称>` 在已有记录开启时切换故事，也会先结算旧故事并开始新故事的计时。
- 不注册或覆盖 `.log`，原生的列表、统计、导出和上传能力保持原样。

## 开始前

1. 安装并启用“日志增强”扩展；它只在群聊中工作。
2. 确认 SealDice 已在该群开启，且原生 `.log` 可以正常使用。若 `.log new` 或 `.log on` 本身报错，扩展不会启动计时，这是为了避免出现没有对应原生日志的错误记录。
3. 若以前安装过“日志进度定位”或“跑团日志计时”裸 JS 插件，请先禁用它们，避免同一条 `.log` 被重复处理。

本扩展不替代原生 `.log`：新建、开启、暂停、结束、上传、导出和检定统计仍请使用 SealDice 原生命令。

## 指令

```text
.logtime [info] [日志名]    查看原生状态、计时状态、累计时长、分段和书签数
.logtime history [日志名]   查看已保存的计时分段
.logtime recap [日志名]     生成可复制的会话摘要
.logmark <标签>             为当前正在记录的日志添加书签
.logmark list [日志名]      查看书签
.logmark show <序号> [日志名] 在 QQ 群中引用书签对应的消息
```

日志名省略时，`.logtime` 和 `.logmark list` 优先使用原生当前日志；原生日志已结束时，则使用插件最近计时的日志。书签只允许添加到正在记录的原生日志，避免将书签写入错误的日志。

## 一次跑团的用法

### 首次开团

团务开始时，像平时一样新建原生日志：

```text
.log new 雾都迷案
```

原生 `.log` 创建成功后，扩展会回复“记录已开始计时”。之后可随时添加关键节点书签：

```text
.logmark 进入旧港区
.logmark 发现失踪者的怀表
.logmark 战斗结束，取得线索
```

书签记录的是发送该命令的消息位置、时间和标签；它不改变原始跑团日志的内容。

需要确认目前进度时，直接发送：

```text
.logtime
```

它会显示原生日志是否正在记录、插件计时是否运行、累计时长、已保存的分段数和书签数。

### 中途暂停与下次续团

中途休息或散团时，正常暂停原生日志：

```text
.log off
```

原生暂停成功后，扩展会停止本次计时，显示本次与累计时长，并把这条 `.log off` 消息记为该群最新的结束位置。

下次继续时可以明确指定日志名：

```text
.log on 雾都迷案
```

也可以使用 SealDice 原生的“恢复最近日志”方式：

```text
.log on
```

原生日志成功开启后，扩展会恢复对应计时。QQ 群中若保存了结束位置，机器人会引用那条消息，方便快速回到上一次记录结束处。

### 团后整理

结束本团时仍使用原生命令：

```text
.log end
```

然后可以查看本团留下的辅助信息：

```text
.logtime history 雾都迷案
.logmark list 雾都迷案
.logtime recap 雾都迷案
```

`history` 列出每次开启到暂停/结束的计时分段；`recap` 生成便于复制到群公告、团务帖或档案中的时长与书签摘要。日志正文的重新上传、导出与检定统计仍用原生 `.log get`、`.log export`、`.log stat` 等命令。

## 书签使用说明

书签适合记录需要回看的剧情节点、战斗开始结束、重要线索或休息点。添加书签时必须有一个正在记录的原生日志：

```text
.logmark 第三幕开场
```

查看当前或指定日志的书签：

```text
.logmark list
.logmark list 雾都迷案
```

QQ 群中可以引用某条书签对应的消息：

```text
.logmark show 2
.logmark show 2 雾都迷案
```

序号以 `list` 的显示顺序为准。`show` 依赖 QQ 消息 ID；其他平台、缺失消息 ID 或平台已无法引用旧消息时，会提示无法引用，但书签的时间和标签仍会保留。

## 查询与摘要

| 需求               | 命令                        | 说明                       |
| ------------------ | --------------------------- | -------------------------- |
| 看当前计时状态     | `.logtime`                  | 日志名可省略。             |
| 看指定日志         | `.logtime info 雾都迷案`    | 原生日志已结束后也可查询。 |
| 回顾开团与暂停时间 | `.logtime history 雾都迷案` | 按时间顺序列出保存的分段。 |
| 复制团务摘要       | `.logtime recap 雾都迷案`   | 包含累计时长和书签清单。   |
| 列出原生日志       | `.log list`                 | 这是 SealDice 原生功能。   |
| 导出或重新上传     | `.log export`、`.log get`   | 这是 SealDice 原生功能。   |

## 数据与兼容性

每个群和日志名会保存独立的辅助元数据：稳定标识、计时分段和书签。该元数据不读取、不修改原生日志内容或数据库。

1.1.0 会继续使用 1.0.x 的累计计时记录；分段历史从升级后第一次启停时开始建立。没有尝试迁移旧裸 JS 插件的数据。1.1.1 将运行时扩展标识统一为 `sealdice-log-enhanced`，因此不会读取旧标识 `log-enhanced` 下的插件侧数据。

1.2.0 为计时和分段元数据加入了自动对账。原生日志确认开启或停止，而插件侧记录缺失、已经暂停或残留活动分段时，扩展会建立可用的状态并在 `.logtime info` 的“同步状态”中说明原因。无法由插件现有数据确认的活动时长不会计入累计，避免错误放大时长。

分段和书签按“群 + 日志名”隔离。同名日志在不同群中的计时、书签互不影响；同一群内重新使用同名日志会继续累加该名称已有的插件侧计时数据。

## 文案配置

扩展配置中的“文案”分组包含全部回复模板，键以 `message.` 开头。每项可填写多条候选文案，插件会随机选择一条；模板支持 SealDice 原生语法。模板的变量说明会显示在对应配置项中。

“日志增强”分组还提供两个保留上限：每份日志最多保存 30 个计时分段和 50 个书签，可设置为 1 至 100。达到上限时会保留最新数据。

## 常见情况

**原生 `.log` 回复失败，但没有看到计时回复。**

这是预期行为。扩展会先确认原生日志的状态已经实际转换，再启动或停止计时。请先按原生日志的报错处理，例如检查骰子是否已在群内开启、日志名是否存在。

**`.logtime` 提示找不到记录。**

这表示该群尚未通过本扩展成功启停过对应日志，或没有提供可识别的日志名。先使用 `.log new <名称>` 或 `.log on <名称>` 成功开启一次，之后可用 `.logtime <名称>` 查询。

**暂停后又执行了 `.log end`。**

计时会在成功 `.log off` 时停止，随后 `.log end` 不会重复累加时长；结束位置会更新为实际执行 `.log end` 的消息。

**书签和日志正文不一致。**

书签是扩展自己的辅助数据，不写入、不编辑原生日志正文。请用 `.logtime recap` 取得书签摘要，并用原生导出功能取得完整日志。

## 开发

本项目使用 `sealwrapper` 锁定 SealDice 1.6.0 的类型契约、包校验和 fake-QQ 场景：

```sh
mise install
npm ci
npm run verify
npm run package
```

发布前请禁用旧的“日志进度定位”和“跑团日志计时”裸 JS 插件，避免同一条 `.log` 指令被重复处理。
